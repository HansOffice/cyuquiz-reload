CyuQuiz-Reload 使用文档

CyuQuiz-Reload 是 Cyu 系列互动问答与定时答题插件，支持多文件独立题库目录、世界空间感知分发、原版音效线索题、奖池滚存累加、前三名阶梯领奖、答题荣誉段位、全服狂热时刻与五重防脚本秒答拦截。

专为 Paper / Folia / Legacy 三端物理分流打造，提供敏感级并发安全调度与黑盒级服主运维体验。

多文件独立题库 奖池滚存与狂热 五重防脚本拦截 原版音效线索题

安装与升级

安装阶段操作步骤运行表现
放置运行包 根据服务端类型选择 cyuquiz-reload-{paper|folia|legacy}-1.0.4.jar 放入 plugins 目录 单端物理原生直连，零冗余运行时
首次启动 重启服务器或加载插件 自动生成 config.yml、lang/ 多语言文件以及 quizzes/ 目录下的 5 套开箱题库
平滑升级 直接覆盖新版本 jar 文件并启动 内建升级管理器自动继承历史自定义参数，并将旧配置完整备份归档至 backup/ 目录
旧版题库兼容 从旧版单文件 quizzes.yml 升级 插件启动时自动平滑迁移至 quizzes/legacy.yml，既有题库数据零丢失

核心配置指南

主配置文件 config.yml 控制出题节律、世界黑白名单、存储引擎以及全服特色玩法：

# 出题间隔（秒）
quiz-interval: 1800

# 语言设置（对应 lang/ 下的 zh_cn.yml / en_us.yml）
language: zh_cn

# 智能出题休眠（全服在线人数低于该值自动暂停出题计时）
pacing:
  min-players: 1

# 世界黑白名单过滤
world-filter:
  mode: BLACKLIST
  worlds:
    - "world_nether"
    - "pvp_arena"

# 奖池滚存机制
jackpot:
  enabled: true
  money-increment: 200.0
  max-multiplier: 5

# 阶梯领奖机制（前几名均可获奖）
tiered-rewards:
  enabled: true
  max-ranks: 3
  ratios:
    1: 100
    2: 60
    3: 30

# 全服狂热时刻
fever:
  enabled: true
  threshold: 20
  duration-seconds: 180
  quiz-interval-seconds: 30
  reward-multiplier: 2

多文件题库系统 (quizzes/)

每个 quizzes/*.yml 文件代表一个独立题库，文件名即为题库唯一标识。插件预装 5 套开箱即用题库：

题库文件题库名称设计定位与体感表现
minecraft.yml 原版生存 覆盖合成配方、烟熏炉烧炼、红石侦测器脉冲刻数、活塞推拉方块上限与附魔互斥，包含单选、多选与输入抢答
sound_clues.yml 声音侦探 原版音效辨识特色题，出题时同步向全服玩家播发原版声音（苦力怕引线声、恶魂蓄力声、末影人瞬移声、女巫笑声、铁砧敲击声）
dimensions.yml 异界探秘 空间感知绑定题库（worlds: ["world_nether", "world_the_end"]），仅当玩家处于下界或末地时优先匹配出题
safety.yml 服规与安全 普及反诈骗安全常识（管理员索要密码防骗、现金买卖风险、恶性漏洞汇报守则），强化社区文明生态
general.yml 趣味百科 大洋地理面积、水分子元素构成、Mojang 官方“特性”梗，增加日常公屏活跃气氛

题库条目格式示范

name: "声音侦探"
enabled: true
weight: 40
worlds: []
questions:
  - id: snd_creeper_fuse
    text: "仔细听正在播放的声音线索，这是什么声音？"
    type: single
    sound-clue: ENTITY_CREEPER_PRIMED
    options:
      A: "苦力怕即将自爆的引线声"
      B: "营火烤肉的滋滋声"
      C: "下界传送门启动声"
    answer:
      - A
    difficulty: easy
    messages:
      question: "🎧 &b{bank_name}&f · {difficulty} &b{player_name}&f，请辨听：&9{quiz_id}&f → {question}"
      on-correct: "✅ &a听觉灵敏！&b{player_name}&f 抢答正确！正确答案：&9{correct_option}&f 🎉"
      on-wrong: "❌ &c听错啦 &b{player_name}&f，答案 &9{option}&f 不对！"
    rewards:
      - "console:money give {player_name} 600"
      - "console:exp give {player_name} 10"

特色玩法机制

机制名称游戏内体感表现服主运维价值
奖池滚存 (Jackpot) 题目倒计时结束无人答对时，奖金倍率自动叠加至下一题（最高 5 倍） 打破无人答题时的冷场尴尬，奖池累加极大激发后续查阅资料抢答热情
阶梯领奖 (Tiered) 第一名 100% 奖励，第二名 60%，第三名 30%（名次与比例均可在主配置自定） 避免单人独占所有奖励，鼓励手速稍慢的普通玩家积极参与互动
狂热时刻 (Fever) 全服累计答对达标后进入狂热时刻，屏幕中央弹出大标题，出题缩短至 30 秒且双倍奖励 将个人孤立答题行为转化为全服协同合作的群聚高潮事件
荣誉段位 (Ranks) 累计答对题数自动晋升童生、秀才、举人、进士直至状元，支持 PAPI 变量调用 提供长线成长追求，无缝对接聊天称号系统或计分板
智能休眠 (Pacing) 在线人数低于设定值时暂停出题任务 深夜或服内无人时不空跑任务、不刷屏日志、不浪费奖池资源

防脚本安全防线

防御防线运作机制与体感表现
生理反应时间拦截 出题后低于 min-reaction-ms（默认 800ms）提交答案判定为脚本秒答并拦截
动态作答令牌 聊天栏按钮作答时生成一次性随机 Token（如 /cyuquiz answer tk_9f2a1b），拦截固定宏与封包嗅探
同 IP 并发限制 单道题目限制同一 IP 仅允许指定数量玩家作答，防止群开小号刷取奖金
连续答错冷却 短时间内连续答错达到阈值自动进入惩罚冷却期（默认禁答 30 秒），阻断暴力穷举
游戏时长门槛 可设定玩家最低在线分钟数要求，拦截刚注册的初始小号

定时活动场次

events 用于配置每天固定时间自动开启的限时答题赛事（如晚间答题）。活动期间日常出题自动让道，活动结束后自动结算并发放参与奖与前三名排名奖：

events:
  evening:
    enabled: true
    name: "晚间抢答赛"
    worlds:
      - "world"
    start-time: "19:00"
    end-time: "19:30"
    question-count: 15
    question-interval-seconds: 60
    answer-seconds: 45
    pool:
      banks:
        - "minecraft"
        - "sound_clues"
      difficulties:
        easy: 5
        normal: 7
        hard: 3
    rewards:
      participation:
        - "console:money give {player_name} 200"
      top:
        1:
          - "console:give {player_name} diamond 3"
        2:
          - "console:give {player_name} diamond 2"
        3:
          - "console:give {player_name} diamond 1"

报错与异常排查速查

异常现象根本原因解决办法
启动提示 Unknown sound '...' 题目中配置的音效枚举名在当前服务端版本不存在 检查该题目的 sound-clue 或 difficulties.sounds，确认该音效是否支持当前 MC 版本（如 1.16.5 不支持 1.19+ 的守卫者音效）
玩家作答提示 作答速度过快 玩家手速过快或使用了宏指令，触发了 min-reaction-ms 防护 正常玩家一般需 800ms 以上反应时间；若觉得过严可在 config.yml 中将 min-reaction-ms 调低（如设为 500）
某些世界收不到题目广播 触发了全局世界黑名单或该题库设置了限定世界 检查主配置 world-filter 是否将该世界加入了黑名单，或者该题库的 worlds: [...] 是否限定了其他世界
题目出现无人答对但奖池没有倍增 未开启奖池滚存或已达上限 检查 jackpot.enabled 是否为 true，以及是否已达到 max-multiplier 上限
重启后答题统计丢失 启用了 MySQL 但连接失败，或本地 stats.yml 权限异常 检查控制台数据库报错日志；若无需跨服同步，直接保持 database.use-mysql: false 本地持久化即可

运维最佳实践

1. 因地制宜配置题库：在生存主世界开启 minecraft.yml 与 sound_clues.yml，在下界末地通过 dimensions.yml 强化探索氛围。

2. 狂热时刻配合晚间赛事：将全服狂热时刻阈值设为 20~30 题，与晚间抢答赛配合使用，可在活动期间激发玩家极高的互动粘性。

3. 防作弊参数合理设置：启用 dynamic-token: true 彻底屏蔽连点宏；如存在同网吧多开玩家，可将 max-answers-per-ip 调整为 2~3。
